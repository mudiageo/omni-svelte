# Auth Schema Integration

`omni-svelte` integrates your application schemas directly with Better Auth tables through the **Auth Registry** and **Reference API**.

## Referencing Auth Tables

When the auth tables are generated in `.omni/auth-schema.ts`, `omni-svelte` automatically introspects them and generates `.omni/auth-registry.d.ts`. This provides typed table names on the `auth` reference exported from `omni-svelte/schema`.

```ts
import { defineSchema, field, auth } from 'omni-svelte/schema';

export const postSchema = defineSchema('posts', {
  id: field.serial().primaryKey(),
  title: field.string().required(),
  // Type-safe reference to the Better Auth 'user' table
  authorId: field.reference(() => auth.user).required(),
});
```

You can also use string keys:

```ts
authorId: field.reference('user').required(), // This works only for auth or internal tables and not user defined tables
```

## Primary Key Type Inference

You don't need to manually configure column types for foreign keys. `field.reference()` automatically inspects the target's primary key:

| Target Primary Key Type | PostgreSQL | MySQL | SQLite | Zod Validator |
| --- | --- | --- | --- | --- |
| `text` | `text()` | `varchar(255)` | `text()` | `z.string()` |
| `uuid` | `uuid()` | `varchar(36)` | `text()` | `z.string().uuid()` |
| `serial` / `integer` | `integer()` | `int()` | `integer()` | `z.number().int()` |
| `bigint` | `bigint({ mode: 'number' })` | `bigint({ mode: 'number' })` | `integer()` | `z.number().int()` |

## Generated Output

### Single-File Format

With `output.drizzle.format` set to `'single-file'`, `omni-svelte` generates `src/lib/db/server/schema.ts`, imports the referenced auth tables, and re-exports the full auth schema:

```ts
// Auto-generated by omni-svelte
export * from '../../../../.omni/auth-schema';
import { user } from '../../../../.omni/auth-schema';
import { pgTable, text, serial } from 'omni-svelte/drizzle/pg';

export const posts = pgTable('posts', {
  id: serial('id').primaryKey(),
  title: text('title').notNull(),
  authorId: text('author_id').notNull().references(() => user.id),
});
```

### Per-Schema Format

With `output.drizzle.format` set to `'per-schema'`, each schema file (e.g., `src/lib/server/db/schemas/posts.schema.ts`) directly imports only the auth tables it references:

```ts
// Auto-generated by omni-svelte
import { user } from '../../../../../.omni/auth-schema';
import { pgTable, text, serial } from 'omni-svelte/drizzle/pg';

export const posts = pgTable('posts', {
  id: serial('id').primaryKey(),
  title: text('title').notNull(),
  authorId: text('author_id').notNull().references(() => user.id),
});
```

## Drizzle Kit Configuration

When `.omni/auth-schema.ts` is present, `omni-svelte` automatically configures your `drizzle.config.ts` to include both your application schemas and the auth schema in the `schema` array:

```ts
// Auto-generated by omni-svelte. Run `pnpm dev` to refresh.
import { defineConfig } from 'omni-svelte/drizzle/kit';

export default defineConfig({
  // Single-file mode:
  schema: ['./src/lib/db/server/schema.ts', './.omni/auth-schema.ts'],
  // Or per-schema mode:
  // schema: ['./src/lib/db/server/**/*.ts', './.omni/auth-schema.ts'],
  out: './drizzle',
  dialect: 'postgresql',
  dbCredentials: { url: process.env.DATABASE_URL },
  verbose: true,
  strict: true,
});
```

This enables Drizzle Kit commands (`drizzle-kit push`, `drizzle-kit generate`, `drizzle-kit migrate`) to discover and migrate Better Auth tables alongside your application tables seamlessly.

## Read-Only Auth Models

OmniSvelte automatically generates typed read-only models for your Better Auth tables (such as `User`, `Session`, `Account`, and `Verification`) under your model directory (e.g. `src/lib/models/auth/` or `src/lib/db/models/auth/`).

These models inherit from `ReadonlyModel` and provide read-only query capabilities (`find()`, `findMany()`, `query()`) without mutation methods (`create()`, `update()`, `delete()`):

```ts
import { User } from '$models/auth';

// Read queries work as expected:
const user = await User.find(userId);
const activeUsers = await User.query().where('emailVerified', true).get();

// Compile-time error: Property 'create' does not exist on type 'typeof User'
await User.create({ email: 'new@example.com' });
```

### Resource Write Guards (`AUTH009`)

When serving auth models through `resource()`, only read operations (`list`, `get`) are exposed. Attempting to write to auth tables via `resource()` is blocked at both compile-time and runtime:

```ts
import { resource } from 'omni-svelte';
import { User } from '$models/auth';

export const { list, get } = resource(User);

// @ts-expect-error create is not exposed on read-only resources
resource(User).create;
```

If write operations are invoked or specified in `only: ['create']`, an `AUTH009` diagnostic is raised directing you to use the Better Auth API (`authClient.signUp`, `auth.api.updateUser`, or admin plugins) to maintain auth state integrity.

### Code Generation Overrides

You can customize or disable model generation for specific auth tables in your `omni.config.ts`:

```ts
export default {
  auth: {
    generate: {
      session: { model: false }, // Skips generating Session model
    }
  }
};
```
